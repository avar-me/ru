# ru.avar.me: переход словаря на v2

Дата: 2026-09-30. Статус: план, без изменения приложения и деплоя.
Общий план: [sources](../../sources/plans/schema-v2/README.md).
Проект схемы: [спецификация](../../sources/av-ru-schema-evolution-plan.md).

Сейчас `build.sh` скачивает JSONL, `src/build_data.py` обрабатывает
старые морфологические поля и see_also. Код похож на dev, но локальные
отличия существуют: не заменять файлы целиком копией из dev.

## Задачи

1. Получить последний старый av-ru, пересобрать и проверить текущий сайт.
   Записать SHA-256 и коммит sources. Сохранить возможность отката.
2. Не допускать сборку старого парсера с новым входом через cron или push.
3. После приёмки dev перенести согласованные изменения парсера/рендеринга,
   сохранив профиль ru, настройки сборки и собственные отличия.
4. Выбрать новый URL отдельно для av-ru; предлагаемый адрес:
   `https://sources.avar.me/data/v2/av-ru.jsonl`. ru-av пока остаётся v1.
5. Обработать literally на уровне значения и примера, links на уровне
   статьи и значения, forms_dict для отображения/поиска.
6. Сохранить комментарии, номера значений, омонимы, разрешение ссылок
   по всем существующим массивам форм и нестандартным целям.
7. Проверить HTML и TMA, чанки и кеш. При изменении выходной структуры
   согласовать её с app.js и обновить build_id.
8. Выпустить только после проверки новой сборки и согласования переключения.

Приёмка: буквальный перевод + comment, несколько links, омонимы,
типизированные формы по классам/значениям, поиск по формам, неизвестные
необязательные поля этапа 2, обновление клиента со старым кешем.
Проверить, что русский обратный словарь не мигрирован случайно.

v2 охватывает оба этапа. На этапе 2 id/hash/cefr/origin необязательны;
неизвестные поля игнорируются. Старый формат не поддерживается постоянным
экспортом: последний v1 заморожен. Для отката использовать прежний код
и закреплённый v1-вход, а не новый JSONL со старым парсером.

Словари правятся только в sources. Этот файл не авторизует деплой.
